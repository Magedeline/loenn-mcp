## 3. What the current MCP can do (verified)

- **Read:** list maps, overview, room detail, fg/bg tile grids, entities, triggers, decals, stylegrounds, metadata, room settings, dependencies (`everest.yaml`), audio events.
- **Write:** add/update/move/remove entity and trigger, set tiles, add/remove/clone/rename/move/resize room, create map, decals, stylegrounds, metadata. All 30 write sites go through `cb.write_map` (serialize → re-parse check → temp file → rotate `.bak1..3` → atomic replace).
- **JSON:** `map_to_json` / `json_to_map` (typed, byte-identical, refuses lossy writes); `check_authoring_json` / `merge_json_into_map` (loose authoring JSON with Lönn defaults filled in, dry-run diff, placement checks, additive only); `run_author_script` (Node).
- **Mod checks:** `find_missing_definitions`, `audit_plugin_coverage`, `validate_audio` (GUIDs + FMOD banks).
- **Game link:** `game_status`, `game_reload_map`, `game_teleport`, `game_play_tas`, `game_log` over Everest DebugRC (`http://localhost:32270`). Celeste was not running during this audit, so these were only unit-tested.
- **Preview:** `render_map_html`, ASCII previews.
- **Generation:** pattern library, Perlin/Voronoi terrain, image-to-map. None of it is Metroidvania-aware.

Test run: `python -m unittest discover -s tests -v` → 48 OK, 2 skipped (`LOENN_MCP_TEST_MAPS` unset). Separate run of every live CEL map through both round trips: 82 byte-identical, 0 differ, 0 errors, 38 s.

## 4. What is broken or missing against your requirements

1. **No editor integration.** `install_loenn_manager` writes `loenn_mcp_manager.lua` into `Loenn/plugins/`. Lönn never loads that folder (it loads `entities, triggers, effects, libraries, tools, scenes, save_sanitizers, ui/windows, ui/themes, ui/forms/fields` from a mod's `Loenn/`, plus `scripts` via LoennScripts). The plugin also calls a `lonn.registerPlugin` API that does not exist and `socket.http`, which is not bundled. It is dead code and a copy of it sits in the live CEL mod. Remove both.
2. **Write policy.** In-place writes with rolling `.bak1..3`. Your rule is timestamped copy/backup and never a silent overwrite of the source. Needed: a timestamped backup store, an `output_path` on every mutating tool, and a copy-only mode.
3. **Diff.** `compare_maps` reports counts from a snapshot; `summarize_map_diff` needs the wiki cache. No room-level or entity-level diff. After Lönn saves, the file is re-encoded (new string table, rooms sorted when `sortRoomsOnSave = true`), so byte comparison is useless and a semantic diff is required.
4. **Validate.** Spawn / floor / bounds / 8px dimensions only. No exit alignment, reachability, entity-definition or asset checks.
5. **Sprites-first.** `lua_defs.py` does not extract `texture`; nothing reads `Graphics/Sprites.xml` (402 sprite ids) or checks atlas PNGs. `find_missing_definitions` is the closest thing.
6. **Adapter.** None; Lönn-specific paths are hard-coded in catalog lookups.
7. **Tool surface.** 88 tools with long docstrings; `terrain`, `image`, `wiki`, `ingest_external_map` and `install_loenn_manager` are noise for an agent driving map edits.
8. **Uncommitted work** in `loenn-mcp` (the entire JSON/authoring layer) must be committed before the rework, or the rework diff is unreviewable.
9. **The delta's useful parts** (`pcg_helper`, `rando`, `verify`) are not in the engine you are keeping. The PCG design needs `verify/` (T1/T2) and `rando.py` (hole detection); they are stdlib-only and port cleanly. `ai_analyzer`, the GAN and `rysy-plugin` are not needed.
10. **Two CEL checkouts.** Every path in the task points at the stale Steam copy. The MCP workspace must be the Desktop copy or the game and Lönn never see the edits.

## 5. Lönn: what actually works on this Windows setup

Source read from the fused exe (`launch_arguments.lua`, `conf.lua`, `scenes/loading.lua`, `loaded_state.lua`, `backups.lua`, `file_locations.lua`, `input_handler.lua`, `mods.lua`) and tested with Lönn 1.0.10 from Olympus.

| Mechanism | Result |
|---|---|
| `Lönn.exe <abs path to map.bin>` | **Works.** Positional arg → `initialFilename` → loaded in the Loading scene instead of `lastLoadedFilename`. Test: window title `Lönn - launch_test`, `persistence.lastLoadedFilename` = the test file, 25 s to load with all your mods. |
| `--storage-directory <dir>` | **Works.** Settings, persistence, backups, plugin settings and `run.log` go to that dir. Copying `settings.conf` there gives an isolated instance that still mounts the same `Mods/`. Used for both tests so your real `persistence.conf` and recent-files list were untouched. `--portable` is the same with `.\Loenn`. |
| Open a specific room | **Works via persistence.** Lönn reads `persistence.lastSelectedRoomName` (and `cameraPositionX/Y/Scale`) at load. Seeding `lastSelectedRoomName = "p3"` on a 3-room map opened on `p3`; unseeded it opened on `p1`. There is no command-line room argument. |
| Tell a *running* Lönn to open or reload a file | **Not possible today.** No IPC, no single-instance guard: a second launch is a second window. Options: (a) only launch when Lönn is not running (`persistence.currentlyRunning` + our own process handle); (b) later, a small Lönn library plugin that injects an input device with `update(dt)` (exactly how AnotherLoennPlugin adds its modules) and polls a request file, then calls `loadedState.loadFile(path, room)`. (b) is feasible and ~60 lines of Lua; it is phase 2, not phase 1. |
| Detect "edit finished" | **Watch the file.** Save = write `<map>.bin.saving` → decode-verify → delete target → rename. So: poll mtime/size/sha256 of the `.bin`; a change plus no `.saving` sibling means a completed save. `persistence.currentlyRunning` is `true` while Lönn runs, but it stayed `true` after my forced kill, so it is a hint only; the process handle of an instance we launched is the reliable signal that Lönn closed. |
| Lönn's own backups | `%LOCALAPPDATA%\Loenn\Backups\<package>\YYYY-MM-DD HH-MM-SS.bin`, every 60 s when there are changes, max 50 files (from `settings.conf`). Independent of ours. |
| Drag-and-drop | `love.filedropped` → `loadFile`. Not scriptable. |
| Rysy (for the adapter later) | `Rysy.exe --map <bin>` / `<bin>` as last arg; `--script <file.cs>` headless. Read from `CommandlineArguments.cs`; not run. |
